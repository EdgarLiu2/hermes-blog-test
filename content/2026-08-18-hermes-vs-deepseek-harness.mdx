# Hermes Agent 与 DeepSeek Harness：同为"智能体外壳"，为何一个拿来就用、一个拿来改装？

你有没有想过这样一个问题：同样是大模型，为什么 ChatGPT 只能"回答"，而真正的 AI 助手却可以帮你订机票、查资料、改代码、定时发消息？中间的差距，靠的并不是更聪明的模型，而是一层常常被忽略的"外壳"。

2026 年的 AI 圈里，有两个项目恰好代表了这层外壳的两种不同哲学：一个是 Nous Research 出品的 **Hermes Agent**，另一个是 DeepSeek 开源的 **DeepSeek Harness**。它们都宣称自己是让 AI"动起来"的运行环境，但一个面向"拿来就用"的用户，一个面向"拿来改装"的开发者。

这篇文章想用最直白的方式，讲清楚它们分别是什么、区别在哪、又为什么说它们是"同类不同路"。

## 先弄懂一个概念：什么是 Harness？

要理解这两个项目，得先理解一个公式：**Agent = Model + Harness**。

这句话是 DeepSeek 官方喊出来的，但它对 Hermes 同样成立。拆开看：

- **Model（模型）**：就是那个"会想"的大语言模型。它能理解语言、做推理，但它坐在原地，什么都碰不到。
- **Harness（外壳/运行环境）**：是让模型"会做"的那层身体。它负责给模型接上工具（读文件、跑命令、查网页）、管理对话上下文、让模型在真实世界持续执行多步任务。

你可以把 Harness 想成一个"接线员"：一头连着只会思考的模型，一头连着真实世界的工具和平台。没有它，模型是困在脑内的思考者；有了它，模型才成为能在现实里干活的智能体。

**为什么这个概念重要？** 因为它解释了 AI 行业的一个普遍规律：模型越来越同质化，真正拉开体验差距的，往往是这层"外壳"做得好不好。而 Hermes 与 DeepSeek Harness，正是这层外壳的两种标杆性实现。

## Hermes Agent：开箱即用的"全能助手"

Hermes Agent 由 **Nous Research** 出品，技术栈是 **Python**，目前已是生产级版本（v0.20.x）。它的产品定位一句话就能说清：**一个开箱即用、越用越聪明的个人全能助手**。

它的核心卖点有三个：

**第一，多平台接入。** 一个网关进程，同时驱动 CLI、桌面 App、Telegram、Discord、Slack、WhatsApp、Signal、飞书、企业微信、QQ Bot 等 **20+ 平台**。你不用为每个聊天软件各装一个 AI，而是让同一个智能体统一接管。

**第二，记忆与技能的自我进化。** 这是 Hermes 最独特的地方：它有一个内置的"学习闭环"。它会跨会话记住你是谁、你的偏好、你的环境（记忆）；还会在使用中**自主创建技能、并自我改进**（技能）。也就是说，它不只是执行任务，还会从任务里沉淀经验，越用越懂你。

**第三，模型无关。** 它不绑定任何一家模型，可以接 OpenRouter、OpenAI、Anthropic、DeepSeek、xAI，也能接本地模型，运行中还能用 `/model` 随时切换。

如果你是个普通用户或小团队，只想装一个就能在微信、飞书、邮件、终端里统一指挥的 AI 助手——Hermes 就是为这个场景而生的。

## DeepSeek Harness：可拼装的"乐高机器人"

DeepSeek Harness 由 **DeepSeek** 出品，技术栈是 **TypeScript / Node.js**，目前处于开发者预览版（**0.1.0-rc**，MIT 许可证）。它的产品口号更能说明问题：**"Everything is a plugin"（一切皆插件）**。

这是什么意思？在 DeepSeek Harness 里，模型、工具、技能、会话、沙箱、存储、循环、调度，甚至 UI——**全部都是可替换、可重组的插件**。开发者不改源码，只靠配置，就能挑选、替换、扩展任何一个能力模块。它的底层构建在 **Cordis 插件内核**之上，这是来自 Koishi 机器人社区的一套插件管理系统。

它还强调**"Every run is traceable"（每次运行都可追踪）**：模型看到的一切——系统提示、推理、工具调用与结果——都会写入只追加（append-only）的会话日志，并提供轨迹（Trajectory）视图。这意味着你可以像逐帧回放一样，审查智能体每一步到底做了什么。

DeepSeek Harness 提供四种运行模式：**Standard**（标准编程智能体）、**Code**（可让模型用一段 TypeScript 程序编排多步操作）、**Minimal**（只有 Shell 和一个文本编辑器，用于基准测试）、**Creator**（给开发者搭自定义预设）。启动方式也很简单：`npx @deepseek-ai/dsh web` 就能打开 Web UI。

如果你是个开发者，想为公司搭建一个内部定制、可插拔、可追踪的智能体运行时——DeepSeek Harness 就是为这个场景而生的。

## 一张表看懂区别

| 维度 | Hermes Agent | DeepSeek Harness |
|---|---|---|
| 出品方 | Nous Research | DeepSeek |
| 定位 | 个人/全能自主智能体（开箱即用） | 面向开发者的可拼装运行环境 |
| 技术栈 | Python | TypeScript / Node.js |
| 成熟度 | 生产级（v0.20.x） | 开发者预览版（0.1.0-rc） |
| 核心卖点 | 多平台接入 + 记忆/技能自我进化 | 一切皆插件 + 全程可追踪 |
| 主要入口 | CLI/TUI、桌面 App、20+ 平台、IDE | Web UI、源码 |
| 面向人群 | 想直接用的用户与团队 | 想自己定制智能体的开发者 |
| 扩展方式 | 插件、MCP、自定义工具、技能、cron | 插件（基于 Cordis），组件全可换 |
| 许可证 | 开源 | MIT |

## 同为 Harness，为何是"同类不同路"？

看完表格，你可能已经感觉到了：这不是"谁比谁强"的竞争，而是**两种不同的产品哲学**。

**它们是同一品类。** 两者都是"Agent = Model + Harness"里的那层 Harness，都在做大模型与真实世界之间的"接线员"，解决同一个问题：让只会思考的模型变成会干活的智能体。

**它们都模型无关。** Hermes 支持多家模型；DeepSeek Harness 的模型接入本身就是可换插件。你完全可以在 Hermes 里用 DeepSeek 的模型，也可以给 DeepSeek Harness 接上别的模型——两者都不锁死某家。

**它们理念同源。** DeepSeek 官方喊出 "Agent = Model + Harness"；Hermes 的每一项能力设计——工具、记忆、技能、多平台——本质上都是在打造这层"身体"。可以说，它们在做的是同一件事，只是侧重不同。

**它们可以互补。** 一个很现实的组合是：用 Hermes 做对外交互层和个人助手（消息平台 + 记忆习惯），用 DeepSeek Harness 做内部定制化的开发运行时（可插拔组件 + 轨迹逐帧调试）。一个管"对外好用"，一个管"对内可改"。

## 你应该怎么选？

如果你只是**想直接用**——希望一个 AI 助手能在微信、飞书、邮件、终端里统一帮你干活，还会记住你的习惯——选 **Hermes Agent**。

如果你是**开发者，想自己动手搭**——希望给团队构建一个可插拔、可追踪、完全可控的智能体——选 **DeepSeek Harness**。

最后留一个提醒：DeepSeek Harness 目前还只是候选版（0.1.0-rc），正式版尚未发布；如果你在网上搜到同名的"deepseek-harness"第三方项目，注意区分，一定要认准官方仓库 `deepseek-ai/deepseek-harness`。

**为什么这个话题值得你花这几分钟？** 因为"Agent = Model + Harness"正在成为整个 AI 行业的下一个共识。今天你理解了这层"外壳"，明天再看到任何"AI 助手""智能体框架"时，你都能一眼看穿它到底在解决什么问题——这正是 AI 时代最有价值的元能力之一。
